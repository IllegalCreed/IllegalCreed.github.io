# 文本处理

服务器上的日志、配置、命令输出都是文本——Nginx access.log 动辄几 GB，`docker ps` 输出几十列，`journalctl` 刷屏不停。怎么从海量文本里**提取、过滤、转换、统计**你要的信息？这就是 Linux 文本处理工具链的用武之地。Unix 哲学的精髓在于**小工具 + 管道组合**：每个工具做一件事（`grep` 过滤、`sed` 替换、`awk` 列处理、`sort`/`uniq` 统计），通过管道 `|` 串成强大的数据流水线。一个一行命令的管道组合，抵得上几十行 Python 脚本。

本叶是**服务器基础工具章**的收官，把文本三剑客（`grep`/`sed`/`awk`）、列处理工具（`cut`/`sort`/`uniq`/`head`/`tail`/`less`/`cat`）、**JSON 处理利器 `jq`**、**管道组合**与**正则表达式基础**汇于一处。讲清每件工具的适用场景（`grep` 按行过滤、`sed` 按行替换、`awk` 按列处理）、正则的基础元字符（`.`/`*`/`[]`/`^`/`$`/`\d`）、以及如何用管道把它们组合成「日志分析」「配置批量修改」「统计 Top10」等实战流水线——这是从「会敲命令」到「能高效处理数据」的关键技能。

## 评价

**优点**

- **管道组合强大**：小工具各司其职，通过 `|` 串成复杂流水线，复用性与表达力极强
- **正则表达力强**：`grep`/`sed`/`awk` 共享正则语法，一行命令完成复杂匹配替换
- **jq 让 JSON 可操作**：命令行处理 API 响应、配置文件不再痛苦，是云原生时代必备

**缺点**

- **正则学习曲线陡**：`.`/`*`/`+`/`?`/`[]`/`()`/`{}`/`\d` 等元字符组合复杂，写错难调试
- **sed/awk 语法晦涩**：单字母选项、`-e`/`-n`、`$1`/`NF`/`FS` 等隐式变量，初学者难记
- **管道调试困难**：长管道出错难定位是哪一环，且大文件管道会一次性读入内存
