# 数据库与用量定价：Postgres、Redis 与按秒计量

> 基于 Railway 官方文档 · 核于 2026-08

## 速查

- **内置数据库**：Postgres、Redis、MySQL、MongoDB 经模板一键部署，Railway 管理备份与连接，连接串（`DATABASE_URL`/`REDIS_URL`）自动注入环境变量。
- **按秒用量计费**：CPU 约 $0.00000772/vCPU·秒、内存约 $0.00000386/GB·秒、磁盘约 $0.00000006/GB·秒、出站流量约 $0.05/GB——用多少付多少，无空闲溢价。
- **Hobby $5/mo 含 $5 额度**：低流量/开发期项目消耗通常在额度内（近乎"白嫖"），超出按量续费。
- **Free Trial**：$5 额度 + 30 天，无需信用卡，每个服务最多 2 vCPU / 1GB——试用探索。
- **用量计费 vs 长驻实例**：低流量选 Railway（省钱），稳定高流量选 Render 长驻（曲线交叉后更便宜）。
- **数据库也按用量**：Postgres/Redis 的 CPU/内存/磁盘/流量同样按秒计费——常驻数据库持续消耗，需纳入成本预估。
- **成本失控风险**：高负载（突发爬虫、高 QPS API、大流量下载）会让消耗暴涨，需设预算告警与资源上限。
- **对象存储与负载均衡**：Object Storage 约 $0.015/GB·月，Load Balancer 包含在套餐内。

## 一、内置数据库：Postgres、Redis 等

Railway 经模板提供托管数据库：

| 数据库 | 用途 | 连接 |
| --- | --- | --- |
| **PostgreSQL** | 关系型主库 | `DATABASE_URL`/`PG*` 系列变量自动注入 |
| **Redis** | 缓存、会话、队列 | `REDIS_URL` 自动注入 |
| **MySQL** | 关系型（替代） | 连接串注入 |
| **MongoDB** | 文档型 | 连接串注入 |

- **一键部署**：在控制台或 CLI 加数据库服务，Railway 自动拉起、配置、注入连接串。
- **自动备份**：付费档支持数据库备份（Free Trial 不保证持久化）。
- **内网连接**：数据库与引用它的服务在 Railway 内网通信，延迟低、不计出站流量。
- **模板市场还有**：ClickHouse（OLAP 分析）、RabbitMQ（消息队列）等。

## 二、用量计费公式：按秒计量

Railway 的计费精确到秒，四类资源分别计价（参考单价）：

| 资源 | 单价（约） | 说明 |
| --- | --- | --- |
| **CPU** | $0.00000772 / vCPU·秒 | 按分配的 vCPU × 运行秒数 |
| **内存** | $0.00000386 / GB·秒 | 按分配的内存 × 运行秒数 |
| **磁盘（Volume）** | $0.00000006 / GB·秒 | 持久化卷按容量 × 秒数 |
| **出站流量（Egress）** | $0.05 / GB | 出 Railway 的流量 |
| **对象存储** | $0.015 / GB·月 | S3 兼容对象存储 |

- **核心思想**：用多少付多少，实例空闲也在分配资源所以也计费（但你可以缩容或暂停）。
- **无"空闲溢价"**：不像某些平台对空闲实例加价，Railway 按纯消耗计费。
- **按秒精度**：部署/重启的几秒也计入，账单精细透明。

## 三、Hobby $5 额度能跑多少？

Hobby 套餐 $5/mo 含 $5 用量额度，典型场景的消耗预估：

| 场景 | 月消耗（估） | 是否在额度内 |
| --- | --- | --- |
| 开发期小型 Web 服务（低流量） | < $2 | ✅ 有余量 |
| 小型 Web 服务 + 小 Postgres（稳定低流量） | $2~$5 | ✅ 接近上限 |
| 中等流量生产 API（稳定 QPS） | $5~$15 | ⚠️ 可能超额 |
| 高流量/高 CPU 应用 | > $20 | ❌ 超额明显，按量续费 |

- **开发期近乎"白嫖"**：一个几乎没流量的开发服务，每月可能只花几毛到一两美元。
- **生产的临界点**：稳定中高流量时，实际消耗可能超过 Render 的固定 $7/mo——这时长驻实例反而更划算。
- **设预算告警**：在控制台设用量阈值告警，避免超额意外。

## 四、用量计费 vs 长驻实例（Render）

理解两种计费模型的成本曲线是选型的关键：

```
成本
  │
  │        Railway（用量）          随用量上升的曲线
  │       ╱
  │      ╱
  │     ╱     ← 交叉点：超过此流量，长驻更便宜
  │ ─ ─ ╱ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
  │   ╱  Render（长驻 $7/mo）     每月固定的水平线
  │  ╱
  │ ╱   ← 低流量时 Railway 更省
  └──────────────────────────── 流量/用量
```

- **低流量/开发期/突发**：选 Railway 用量计费（曲线低位，省钱）。
- **稳定高流量**：选 Render 长驻实例（水平线，超过交叉点后更便宜）。
- **混合策略**：开发/staging 用 Railway（省），生产高负载用 Render 或 K8s（可控）。

## 五、成本控制实践

- **设资源上限**：给每个服务设 CPU/内存上限，防失控消耗。
- **开发期缩容**：非工作时段可暂停或缩容开发服务，减少消耗。
- **监控流量**：出站流量（$0.05/GB）是大头——大文件下载/视频流考虑用 CDN 或对象存储。
- **数据库优化**：常驻数据库持续计费，用连接池（PgBouncer）减少连接数，避免冗余副本。
- **预算告警**：在控制台设月度预算阈值，超额前收到通知。

## 六、选型决策

| 场景 | 推荐 | 原因 |
| --- | --- | --- |
| 个人副业/学习（低流量） | Railway Hobby $5/mo | 用量计费，开发期消耗在额度内 |
| 快速原型/PoC | Railway + 模板市场 | 一键拉起整套服务栈 |
| 稳定中高流量生产 | Render 长驻 / K8s | 曲线交叉后长驻更便宜 |
| 团队协作 + 多环境 | Railway Pro / Render Scale | 支持多环境与权限 |
| 突发流量不可预测 | Railway 用量计费 | 按需伸缩，不过度配置 |
