# 入门：阿里云开发者产品全景与本站实际栈

> 基于阿里云 · 核于 2026-08

## 速查

- **阿里云定位**：国内份额第一、全球前三的公有云，从双 11 电商基础设施起步，产品矩阵覆盖计算/存储/网络/数据库/AI。
- **计算层两选**：①**ECS**（弹性计算服务，虚拟服务器，规格/镜像/网络全可控，需自管系统）；②**轻量应用服务器**（开箱即用，自带应用镜像，价格低，面向个人/小项目）。
- **数据库层两选**：①**RDS**（托管 MySQL/PostgreSQL/SQL Server/MariaDB，自动备份、主备高可用，本站用 RDS）；②**PolarDB**（自研云原生数据库，存储计算分离、读写分离、秒级扩容，性能更高但更贵）。
- **对象存储 OSS**：S3 兼容的**对象存储**，按容量+请求计费，放图片/视频/静态资源/备份；通过 **Endpoint**（地域级域名）访问，可挂 CDN 加速。
- **加速两件套**：①**CDN**（内容分发网络，加速**静态资源**，把源站内容缓存到全国边缘节点）；②**DCDN**（全站加速，动态+静态混合，加速**动态 API**）。
- **函数计算 FC**：**Serverless** 函数（事件驱动，按调用次数+执行时长计费，毫秒级计费），适合事件触发/低频/突发场景。
- **本站实际栈**：ECS（跑后端进程）+ RDS（MySQL，托管数据库）+ OSS（静态资源/图片）+ CDN（加速静态），轻量服务器作为备用/测试环境。
- **地域与可用区**：地域（Region，如华东 1 杭州）内多可用区（Zone）做高可用；**跨地域走公网计费**，架构应同地域部署。
- **备案强制**：境内 ECS/轻量对外提供 80/443 服务**必须完成 ICP 备案**（详见[ICP 备案与域名](../../icp-filing/) 叶）。
- **边界**：本叶只讲开发者产品；大数据（MaxCompute）、AI（通义/PAI）、企业级中台不讲；Linux 命令归[服务器基础](../../../server-basics/) 章。
- **进阶顺序**：[ECS 与 RDS：本站实际栈](./guide-line/ecs-and-rds) → [OSS 与 CDN](./guide-line/oss-and-cdn) → [参考](./reference)。

## 一、阿里云是什么：从双 11 走出的国内头号云

阿里云诞生于 2009 年，最初是为支撑**双 11**（天猫双十一购物节）这种全球罕见的超大规模并发（峰值千万级 QPS）而建的内部基础设施。2010 年代起对外商业化，逐步成为国内公有云市场份额第一（约 40%），全球前三（仅次于 AWS、Azure）。它的核心定位是**全栈公有云**——从底层的计算/存储/网络，到中间的数据库/中间件，再到上层的 AI/大数据/SaaS，几乎覆盖企业 IT 的全部需求。

对**开发者**而言，阿里云的价值在于"**用一组托管产品拼出一个 Web 后端**"：

```
开发者（你）
  ┌─────────────────────────────────────────┐
  │  应用代码（Node.js / Python / Go / Java） │
  └────────────────────┬────────────────────┘
        ECS（虚拟服务器）跑后端进程  ←  计算层
            │              │
            ▼              ▼
        RDS（MySQL/PG）   OSS（对象存储）   ←  数据层
       主备高可用+备份     放图片/静态资源
            │
            ▼
        CDN（内容分发）   ←  加速层
        全国边缘节点缓存
            │
            ▼
        用户（境内低延迟访问）
```

- **同账号互通**：阿里云产品在同一账号/地域内天然互通——ECS 通过内网（VPC）访问同地域 RDS（免公网流量费），ECS 通过 RAM 角色授权访问 OSS（无需硬编码密钥）。这是用全家桶的核心收益。
- **国内访问最优**：节点遍布华北（北京）、华东（杭州/上海）、华南（深圳/广州）、西南（成都）等，备案后境内用户访问延迟低（同省 < 10ms），CDN 加速后静态资源近乎即时。

## 二、计算层：ECS vs 轻量应用服务器

阿里云的虚拟服务器有两条产品线，开发者要清楚何时用哪个：

| 维度 | **ECS（云服务器）** | **轻量应用服务器** |
| --- | --- | --- |
| 定位 | 企业级/通用，灵活可控 | 个人/小项目，开箱即用 |
| 配置 | 规格/镜像/VPC/磁盘/安全组全可控 | 套餐化（CPU/内存/带宽/流量打包） |
| 网络 | 自定义 VPC、弹性公网 IP、多网卡 | 自带公网 IP，带宽固定 |
| 应用镜像 | 需自行装环境 | 自带 WordPress/LNMP/Node.js/Docker 等镜像 |
| 价格 | 按需/包年包月，灵活但门槛高 | 24 元/月起，价格低、无脑选 |
| 适合 | 生产环境、需精细化运维、本站 | 个人博客、测试、学习、小型站 |

- **ECS**：本站后端跑在 ECS 上——选好规格（如 2 核 4G）、镜像（Ubuntu/Alibaba Cloud Linux）、系统盘（ESSD 云盘），配好安全组（只开 22/80/443），通过 SSH 登录部署进程。ECS 灵活但**所有运维（系统更新、安全补丁、Nginx 配置）自己负责**。
- **轻量应用服务器**：对纯新手最友好——控制台一键装 WordPress，自带域名解析与 HTTPS 证书申请，无需懂 Linux 即可上线一个博客。但它的网络/磁盘/安全组是套餐化的，深度定制受限。

一句话：**生产环境用 ECS，个人/学习/小站用轻量**。

## 三、数据库层：RDS vs PolarDB

托管数据库让开发者**不用自己装 MySQL/维护主备/做备份**，阿里云有两条主线：

- **RDS（关系型数据库服务）**：托管 **MySQL / PostgreSQL / SQL Server / MariaDB**，提供**自动备份**（每日全量 + 实时日志）、**主备高可用**（主实例故障自动切换备实例）、**只读实例**（读多写少时分担主库压力）。本站用 RDS MySQL——开发者只需建库建表写 SQL，备份/高可用/打补丁全是阿里云的事。
- **PolarDB**：阿里云**自研的云原生数据库**（兼容 MySQL/PostgreSQL 协议），采用**存储计算分离**架构——存储层共享一份分布式存储（最高 100TB），计算层可秒级横向扩展最多 16 个节点，**读写分离**自动路由。性能比同规格 RDS 高数倍，但价格也更贵，适合**高并发大流量**场景。

| 维度 | RDS | PolarDB |
| --- | --- | --- |
| 引擎 | MySQL/PG/SQL Server/MariaDB | 兼容 MySQL/PG（自研内核） |
| 存储 | 每实例独立存储（最大几 TB） | 共享分布式存储（最大 100TB） |
| 扩展 | 加只读实例（分钟级） | 秒级加只读节点（最多 16） |
| 性能 | 标准 | 数倍于 RDS |
| 价格 | 便宜 | 较贵 |
| 适合 | 通用业务、本站 | 高并发大流量 |

**本站选 RDS MySQL 的原因**：流量不大、成本敏感、MySQL 生态成熟、备份与高可用已足够。

## 四、对象存储 OSS：S3 兼容的海量存储

**OSS（Object Storage Service）** 是阿里云的对象存储，对标 AWS S3，且**完全兼容 S3 协议**——用 AWS S3 SDK 改个 Endpoint 就能访问 OSS。

- **核心概念**：①**Bucket（桶）**——顶层命名空间，名字全球唯一；②**Object（对象）**——存的具体文件（图片/视频/压缩包），由数据+元数据组成；③**Endpoint（接入点）**——访问域名，如 `oss-cn-hangzhou.aliyuncs.com`（杭州地域）。
- **三种读写权限**：①**公共读**（任何人可读，适合图片/静态资源）；②**私有**（需签名授权才能访问，适合敏感数据）；③**公共读写**（任何人可改，**严禁用**，会被刷流量）。
- **典型用法**：用户上传头像 → 后端生成签名 URL → 前端直传 OSS → 后端存 URL；静态资源（JS/CSS/图片）放 OSS + 挂 CDN，就近返回。
- **与 ECS 的配合**：ECS 不建议把大量文件存本地盘（实例故障会丢），应放 OSS；ECS 通过 RAM 角色授权访问 OSS，无需硬编码 AccessKey。

## 五、加速层：CDN 与 DCDN

- **CDN（内容分发网络）**：把**静态资源**（图片/JS/CSS/视频）从源站（OSS 或 ECS）缓存到全国边缘节点，用户就近取，降低延迟、减轻源站压力。源站填 OSS Bucket 域名，CDN 自动回源拉取并缓存。
- **DCDN（全站加速）**：CDN 只能加速静态；DCDN 在静态缓存之外，对**动态请求**（API 调用、登录、查询）走**最优路由回源**（智能选路、长连接复用），适合动态+静态混合的站点（如电商、SaaS）。

本站静态资源（封面图、图标）放 OSS + 挂 CDN，境内访问加速明显。

## 六、Serverless：函数计算

**函数计算（Function Compute，FC）** 是阿里云的 Serverless 函数服务（对标 AWS Lambda）：

- **事件驱动**：由 OSS 上传、API 网关请求、定时任务等**事件触发**函数执行，无需常驻服务器。
- **按量计费**：按**调用次数 + 执行时长 + 内存**计费（毫秒级），空闲时零费用，适合**低频/突发/事件触发**场景（图片处理后缀、定时备份、Webhook）。
- **冷启动**：首次调用或长时间空闲后有冷启动延迟（百毫秒到秒级），不适合长连接/高频实时场景。

本站暂未用函数计算（流量稳定，ECS 常驻更划算），但它是未来事件化改造的选项。
